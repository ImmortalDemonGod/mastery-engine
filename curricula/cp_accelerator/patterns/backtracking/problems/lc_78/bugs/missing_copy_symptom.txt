# Bug Symptom: Missing List Copy in Backtracking

## What You'll Observe

Your solution returns a list of subsets, but they're ALL empty lists.

## Expected Behavior

- `subsets([1, 2, 3])` → `[[], [1], [1,2], [1,2,3], [1,3], [2], [2,3], [3]]`

## Actual Behavior

- `subsets([1, 2, 3])` → `[[], [], [], [], [], [], [], []]`

All 8 subsets are empty lists, even though the correct count (8) is returned.

## Debugging Guide

1. **Add a print inside backtrack**: Print current right before appending. Does it show the right values?
2. **Print result after the function returns**: Are the values there?
3. **Key insight**: You're storing REFERENCES to the same list, not copies

## Conceptual Understanding

In Python, `result.append(current)` stores a REFERENCE to current, not a copy.
As backtracking modifies current (append/pop), all stored references see the
changes. After backtracking completes, current is empty, so ALL stored entries
are empty.

Fix: Use `result.append(current[:])` to store an independent copy.

This is one of the most common Python backtracking bugs and appears in almost
every combination/permutation problem.
